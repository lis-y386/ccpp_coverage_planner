# v0.1.0-alpha.1 — experimental source preview

This alpha makes the standalone C++14 core, ROS1 adapter and reproducible synthetic demonstrations available for evaluation. It is not a stable flight/navigation system.

## Included

- Boustrophedon lattice coverage with four-neighbor A* connectors.
- Explicit arrival confirmations, chunked targets, skip/forbidden zones and ROS frontier handling.
- Six self-contained browser replay scenes generated from actual C++ output.
- Standalone CMake install/export, ROS Noetic examples, documentation and automated checks.

## Validation

The prior validation snapshot passed all three Linux CI jobs: native, browser and headless ROS Noetic. Its evidence and exact scope are in [CLOUD_VALIDATION.md](../CLOUD_VALIDATION.md). The publication process also requires the candidate commit's CI to pass before this prerelease is published. GitHub Release notes link the final candidate run.

Known strict expected failures remain visible. Passing CI does not mean every input is valid or every environment is supported.

## Known defects — read before use

- **H02:** direct C++ callers can receive success for some occupied or adjacent out-of-bounds starts. The ROS adapter already rejects non-FREE/out-of-bounds starts.
- **H03:** Grid::valid accepts positive-infinite resolution.

Direct callers must check that geometry is finite and reasonably bounded, resolution is finite and positive, and the requested start is inside the map and FREE. These defects were deliberately retained; this alpha does not claim they are fixed.

The adapter assumes a fully observed local obstacle-map window. Raw sparse LiDAR returns alone do not establish FREE space. There is no stale-input protection or continuous flight-time collision avoidance.

## Scope

RViz GUI, real sensors/TF, physical robot execution, flight dynamics and other architectures remain unverified. No binary ROS package or Docker image is distributed with this source preview.

The core, ROS node, public header, service schema and original tests still match upstream 8bc54d2. No new algorithm or performance claim is made.

ROS package.xml remains 0.1.0; the GitHub prerelease tag is v0.1.0-alpha.1. The optional Node package is developer tooling, not the released runtime.

## Try it

Open docs/demo.html directly in a browser, or follow the repository README to build the core/ROS package. Release attachments include a standalone HTML replay and a source ZIP with SHA256 checksums.
